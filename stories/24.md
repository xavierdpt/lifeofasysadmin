# Thirty cylinders marked RESV

*Theme: Secrets handling*

The Amiga 3000 came up from the sub-basement on a trolley, with a note from
Facilities saying the computing museum wanted it by the end of the month. It had run
the ion-beam stage in Materials until 2004 and had sat under a bench ever since.
Museum donations go through the same disposal review as anything else leaving the
building: the drive gets imaged, the image gets read, and nothing goes out of the
door until somebody has signed that there are no credentials on it.

Priya took the drive out — a 520 MB SCSI unit, still spinning — put it on a USB
adapter and pulled a full image with `dd`. Imaging took twenty minutes. Reading what
she had imaged took the rest of the week.

An Amiga hard disk has no MBR. Its partition table is the Rigid Disk Block: a chain
of 512-byte blocks living in the first sixteen sectors, each one tagged with a
four-character id — `RDSK` for the disk itself, `PART` for a partition, `FSHD` and
`LSEG` for filesystem code carried on the platter — linked by block number and
checksummed so that each block's longwords sum to zero. `fdisk`, `parted` and
`lsblk` read straight past all of it and report an empty disk.

The program that reads it is `amiga-fdisk`, and the source package builds it into
three binary packages. Two of them are `Architecture: m68k powerpc`, which is to say
they assume the disk you are partitioning is in the machine you are typing on. The
third is `amiga-fdisk-cross`: `Architecture: linux-any`, section `otherosfs`, one
line of description — *This is the version for non-Amiga systems.* Same source, same
RDB parsing, compiled for whatever the archive compiles for, which is the whole
point of it existing separately. The author notes in the README that he wrote the
program on an Intel box and only tested it on his own A3000 afterwards, and that it
appeared to behave the same on little- and big-endian hosts. Without that package,
reading this table means booting an Amiga, and the only Amiga in the building was on
the trolley, going out of the door intact.

```
$ sudo apt install amiga-fdisk-cross
$ amiga-fdisk -l /srv/disposal/a3000-materials.img
Disk /srv/disposal/a3000-materials.img: 16 heads, 63 sectors, 1010 cylinders, RDB: 0
Logical Cylinders from 2 to 1009, 516096  bytes/Cylinder 

   Device  Boot Mount   Begin      End     Size   Pri  BBlks    System
/srv/disposal/a3000-materials.img1    *    *         2      400   201096     0    2  Amiga FFS
/srv/disposal/a3000-materials.img2         *       401      979   291816     0    0  Amiga FFS Int.
/srv/disposal/a3000-materials.img3                 980     1009    15120     0    0  [unknown]
```

`Begin` and `End` are cylinders; `Size` is kilobytes, worked out from the two of
them. The device column is the string you passed with a partition number stuck on
the end, which looks ridiculous against a file path and tells you what the program
expected to be given. `-l` is listing mode: it prints the table and exits instead of
dropping into the interactive prompt, and it reads one 512-byte sector at a time,
reopening the file for each block, because it was built to run inside a boot floppy
with no swap to spare.

The asset record said two volumes, and the first two lines agreed with it: DH0, the
system disk, bootable, two bootblocks; DH1, 285 MB of scan logs. Priya read the
third line four times.

Thirty cylinders at the far end of the disk. 15 MB. Blank under Boot, blank under
Mount, and a System column that said `[unknown]`.

The Mount column comes from the partition block's flag word: an asterisk when the
`PBFF_NOMOUNT` bit is clear, blank when it is set. The Amiga header the program
carries says what the bit is for — *do not mount this partition (e.g. manually
mounted, but space reserved here)*. The README gives the recipe outright: set the
DosType to `RESV` and the flags to noboot, nomount, and the partition "will not
appear in the boot menu nor show up anyhow under Amiga OS". The bit exists because
an Amiga disk was normally shared between systems. You kept AmigaDOS on one
partition and something else on another — Linux/m68k, a swap area, a raw region for
a virtual memory tool — and this flag was how you told Workbench that the space was
taken, so it left the region alone instead of putting up a "Not a DOS disk"
requester on every boot.

`[unknown]` was the listing holding back what it had. `amiga-fdisk` renders a
DosType in two halves: the hex value followed by its four bytes as ASCII, then a
name looked up in a table of the twelve types it knows. Listing mode skips the first
half — the code that builds it sits behind an `if (!list_only)` — and `RESV` has no
entry in the table, so all that survived to the screen was the fallback. The
interactive display prints both halves. Priya copied the image, because interactive
mode is the mode with a `w` command in it and the original was evidence, pointed the
tool at the copy and pressed `p`:

```
/srv/disposal/copy.img3                 980     1009    15120     0    0  0x52455356 = RESV [unknown]
```

`0x52455356`: `R`, `E`, `S`, `V`. Somebody had reserved the last thirty cylinders of
the ion-beam controller's disk and told AmigaOS not to look at them. She quit with
`q` rather than `w` and went at the region with `dd`, using the figures the listing
had already given her — 1008 blocks to the cylinder, so 980 cylinders in and 30
cylinders long.

```
$ dd if=a3000-materials.img of=resv.bin bs=512 skip=987840 count=30240
30240+0 records in
30240+0 records out
$ strings -n 6 resv.bin | head
handover notes, do not delete
changer is scsi id 4, term power off
ion source support 0161 xxx xxxx, ask for Dave
fileserv mount: user mat-backup-svc
password Tr0mb0ne98
```

The thirty cylinders had never been formatted. Somebody running Linux/m68k on this
machine had been writing handover notes straight into the reserved region as raw
bytes, in plain text, on a range of blocks that AmigaOS had been instructed to
ignore — which is why the notes had survived two decades of people using the machine
daily without anyone seeing them.

Priya would have filed it as a historical credential, except that `mat-backup-svc`
had the shape of an account she saw every week: the department's three-letter prefix,
the `-svc` suffix the naming standard had used since long before the NAS was bought.
She tried the password in an LDAP bind that read one attribute and changed nothing.
It authenticated.

The rotation went through at 14:20 that afternoon. The disposal ticket got the
`amiga-fdisk -l` output pasted into it with the third line highlighted, and a note
that `resv.bin` and both images were to be shredded once the museum confirmed
receipt of the hardware. The museum got the drive with its RDB untouched — three
partitions, and thirty cylinders of it still marked RESV.
